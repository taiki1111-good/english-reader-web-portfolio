# 08_development_plan

## 初期開発順序

1. 1件の `passages` データを作る
2. `reader.html` で 1件表示する
3. 単語保存を実装する
4. `vocab.html` で単語一覧を表示する
5. 既読管理を実装する
6. 複数長文対応の一覧を作る
7. デザインを軽く整える
8. `PWA` と `IndexedDB` の検討を行う

## この順序にする理由

- まず教材として最小成立する中心画面を先に作る
- その後、保存状態と一覧系を足す
- 最後に拡張性や見た目を整える

## 当面の完了条件

- 1件以上のライセンス確認済み passage がある
- `reader.html` で読める
- 単語保存ができる
- `vocab.html` で見返せる
- 既読が保持される

## Phase 別開発ロードマップ（ユーザーフィードバック反映版）

### Phase 1（現在）: 最小機能実装

- 長文表示・単語保存の基本形
- 既読管理
- 複数長文対応
- CEFR・語数説明の軽い追加（推奨）

### Phase 1.5（推奨）: UI/UX 改善

- index.html で CEFR・語数の説明表示
- 品詞・和訳の入力フォーム追加（オプション項目）
- reader.html での単語保存ダイアログ改善

### Phase 2（中期）: 単語・イディオム機能強化

**単語情報の拡張**:
- 品詞情報（noun, verb, adjective など）の保存
- 日本語訳の保存
- 英語定義の保存（オプション）

**イディオム機能**:
- 複数単語選択でイディオムとして保存可能に
- `saved_words` に `type: "word" | "idiom"` を追加
- イディオムの構成単語を記録（`component_words` フィールド）

**vocab.html の拡張**:
- 品詞・定義情報の表示
- [Word] / [Idiom] バッジ表示
- タイプ別フィルタ（すべて / 単語のみ / イディオムのみ）

**実装の段階性**:
- Phase 2a: 手動入力での品詞・定義追加
- Phase 2b: イディオム手動マーキング機能
- Phase 2c: イディオムリスト（idiom_patterns.json）の整備

### Phase 3（後期）: 学習補助機能

- イディオム自動検出（事前定義リスト照合）
- タグ・品詞別の統計情報
- 復習優先度の自動計算

### Phase 4+（将来検討）: 高度な機能

- NLP を用いた自動品詞抽出
- 外部辞書API との連携
- IndexedDB への移行
- PWA 化

## パッセージ長さについて（ユーザーコメント対応）

### 現状

- `passages.json` 全体は 100-200語が目標 → **達成済み**
- 個別の文の長さについては明記なし

### 確認項目

実装時に以下を確認:
1. 実際の passages.json データ例で、**文ごとの平均語数**を測定
2. ユーザーが「短すぎる」と感じるかどうかを検証
3. 必要に応じて素材選定基準に「各文は 20-30 語程度が望ましい」と追記

### アクション

- Phase 1.5 以降で素材を追加する際、文の長さを意識する
- 必要に応じて `04_content_data_spec.md` に「文の長さ」ガイドを追記
