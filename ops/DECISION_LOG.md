# DECISION_LOG

## 017 2026-05-17 passage 追加ルールを Level A/B と features で formalize

- 状況: 新しい英文 passage を追加する時の source/license 確認、sentence/token 注釈、dictionary entries、grammar grading、idiom 登録の手順が分散していた。
- 判断: `docs/10_content_addition_workflow.md` を運用手順、`docs/04_content_data_spec.md` をデータ契約として分離し、新規 passage では `features` を明示する。
- 方針: 通常 passage は Level A（reading + vocabulary + review + flashcard compatible）を最低水準とし、文型採点対応 passage は Level B として `features.grammarQuiz: true`, `answerKey`, `grammarRole`, `sentencePattern`, `explanation` を追加する。全 passage に grammar grading は要求しない。
- モデル運用: content contract や長期運用に影響する判断は Codex 5.5 thinking、確定済み仕様に沿う小さな実装は Codex 5.3 とする。

## 016 2026-05-16 reader スマホ語句操作をタップ選択 + 下部バーへ変更

- 状況: reader のスマホ主操作として検討していた「長押し中ポップアップ + 指スライド離し」は、iPhone Safari でOS/ブラウザ側のテキスト選択・コールアウトと競合し、操作が不安定だった。
- 判断: スマホ主操作は長押し前提をやめ、語句をタップして複数選択し、下部固定アクションバーから `S/V/O/C/M/clear/save` を実行する方式に変更する。
- 方針: PC の hover/click + popover は維持し、スマホでは長押しスライドを主操作から外す。tray ステータスバーとは同時表示競合を避ける。

## 015 2026-05-14 フラッシュカードUIを独自の集中学習型へ刷新

- 状況: 現行フラッシュカードのUI/UXが希望イメージと異なり、単語帳アプリに近い素早い表裏確認と、大画面で1枚ずつ進めるモードが必要になった。
- 判断: 既存アプリの画面構成や文言を直接模倣せず、通常の大きな1枚表示、横スクロールカード、大型ポップアップの集中モードを組み合わせた独自UIへ更新する。
- 方針: `flashcard.html` の通常表示を設定直下の大きな1枚カードとして整え、その下にカード列を置く。集中モードでは `前へ` / `次へ`、左右キー、Space / Enter で1枚ずつ進める。

## 011 2026-05-14 復習画面にフラッシュカードモードを追加

- 状況: 復習画面に、暗記シートに加えてフラッシュカード表示、ランダム並び替え、英語先/日本語先の初期表示切替が必要になった。
- 判断: `review.html` の復習UIを拡張し、対象選択（全単語/フォルダ）は既存仕様を維持したまま両モードに適用する。
- 方針: 文書（`docs/02_requirements.md`, `docs/05_ui_flow_spec.md`, `docs/07_test_plan.md`）を先行更新し、その後にHTML/CSS/JSを実装する。

## 012 2026-05-14 フラッシュカードを専用ページへ分離

- 状況: 復習画面内モード切替ではなく、別ページ遷移型のフラッシュカードUI（上部設定ボタン群、下部横並びカード、全画面切替）が必要になった。

- 方針: 文書先行更新後に `flashcard.html` を新設し、対象選択・初期表示・ランダム並び替え・全画面ボタンを実装する。

## 013 2026-05-14 フラッシュカードUIの再定義

- 状況: フラッシュカードの見た目と操作イメージを、設定直下の横一列カードと全画面1枚送りへ合わせる必要が出た。
- 判断: `flashcard.html` の設定UIを選択式（対象/初期表示/並び順）へ統一し、カードの表裏デザインを明確化する。
- 方針: 全画面表示は1枚ずつ表示し、裏面表示後に `戻る` / `次のカード` で前後移動できる操作を追加する。

## 014 2026-05-14 全画面APIを使わず大型ポップアップへ変更

- 状況: ブラウザ全画面APIを使う方式は操作性が悪く、希望する見た目とボタン配置にならなかった。
- 判断: `flashcard.html` の全画面機能は `requestFullscreen` を使わず、大型ポップアップ表示に置き換える。
- 方針: `戻る` / `次のカード` をカード下に置き、その下に `全画面を終了` を配置する。
